### Critical Issue: User-Store Offline

**Discovery Date:** October 3, 2025  
**Severity:** CRITICAL  
**Impact:** HIGH (0 users persisted)  

**Issue Details:**
```
Problem:
├─ user-store service was not running
├─ Workflow F extracted 10 users successfully
├─ Persistence failed silently
├─ Reports claimed "10 users persisted"
└─ Reality: 0 users in database

Evidence:
$ docker ps | grep user-store
(no output - service not running)

$ curl http://localhost:5170/health
curl: (7) Failed to connect to localhost port 5170

$ sqlite3 data/user_store.db "SELECT COUNT(*) FROM users"
0

Discrepancy:
- Reports said: "10 users extracted and persisted"
- Reality: 10 extracted, 0 persisted
- Gap: Aspirational reporting vs actual execution
```

**Resolution:**
```bash
# 1. Start user-store service
docker-compose up -d user-store

# 2. Verify service running
curl http://localhost:5170/health
{"status": "healthy"}

# 3. Re-run demo
python demo_hyper_realistic_parameterized.py \
  --documents 30 \
  --team-size 6

# 4. Verify persistence
sqlite3 data/user_store.db "SELECT COUNT(*) FROM users"
10

# 5. Verify report accuracy
grep "users" cats_effect_crud_demo/reports/Planning_Service_Report.md
"10 users extracted and persisted to user-store"
```

**Post-Fix Verification:**
```
✅ Service Status: user-store running
✅ Users Extracted: 10
✅ Users Persisted: 10
✅ Database Verification: 10 rows in users table
✅ Reports Accurate: All reports show 10 users
✅ Service Check Added: Real-time status verification
✅ Fallback Implemented: Disclaimers if service down
```

**Lessons Learned:**
1. ✅ Always verify service status before claiming persistence
2. ✅ Implement real-time service checks in demo script
3. ✅ Add conditional disclaimers when services offline
4. ✅ Distinguish between extraction (successful) and persistence (depends on service)
5. ✅ Never report aspirational outcomes as actual execution
